# CONN-CADDY-MCP-SDK-CENTRALIZATION — Requirements

Each row defines one requirement. [`status.json`](status.json) holds the generated state.

| ID | Requirement | Verification |
|---|---|---|
| `CONN-CADDY-MCP-SDK-CENTRALIZATION-R001` | **Requests use the governed SDK client.** caddy-mcp must send every vendor request through the SDK governed HTTP client with its resolved TLS profile and SDK auth. It must not build its own session. This row follows `SCION-CENTRALIZED-CAPABILITIES-R001`, `SCION-CENTRALIZED-CAPABILITIES-R003`, `SCION-CENTRALIZED-CAPABILITIES-R008`. Caller chain: arbora fleet.call -> `caddy_mcp_config` or `caddy_mcp_reverse_proxy` tool (caddy_mcp/mcp/mcp_config.py:60) -> caddy_mcp/auth.py::get_client -> caddy_mcp/api_client.py::Api -> caddy_mcp/api/api_client_base.py::ApiClientBase.request. Shape: ApiClientBase.__init__ in caddy_mcp/api/api_client_base.py builds the session with scion_sdk.http.client.create_http_client, HttpClientOptions, resolve_tls_profile("caddy") and scion_sdk.auth.static.BearerAuth or httpx.BasicAuth. | A unit test shows the API client holds an httpx client and a request carries the configured credential through a mock transport Test: `tests/test_sdk_centralization.py::test_request_goes_through_the_governed_client`. |
| `CONN-CADDY-MCP-SDK-CENTRALIZATION-R002` | **SDK floor and dependency set.** The package must require the current scion-sdk floor and must not pin requests or httpx while nothing imports them directly. Optional drivers come from SDK extras. This row follows `SCION-CENTRALIZED-CAPABILITIES-R040`, `SCION-CENTRALIZED-CAPABILITIES-R001`. Caller chain: dependency resolution of pyproject.toml (dependencies = scion-sdk[mcp]) for the `caddy-mcp` console script and the `caddy_mcp:connector` entry point; no runtime code path. Shape: pyproject.toml dependencies hold only scion-sdk[mcp] with the current floor and no requests or httpx pin; caddy_mcp imports httpx only through the SDK client types, and tests read the dependency list with tomllib. | pyproject.toml shows the floor and no unused requests pin Test: `tests/test_sdk_centralization.py::test_dependencies_have_no_unused_requests_pin`. |
| `CONN-CADDY-MCP-SDK-CENTRALIZATION-R003` | **Production wiring and hot path.** `ApiClientBase.__init__` in `caddy_mcp/api/api_client_base.py` calls `create_http_client`, and every domain client reaches it through `request`. A transient 503 is retried by the SDK policy. This row follows `SCION-CENTRALIZED-CAPABILITIES-R001`, `SCION-CENTRALIZED-CAPABILITIES-R003`, `SCION-CENTRALIZED-CAPABILITIES-R008`. Caller chain: arbora fleet.call -> `caddy_mcp_config` tool (caddy_mcp/mcp/mcp_config.py:60) -> caddy_mcp/api/api_client_config.py::Api methods -> caddy_mcp/api/api_client_base.py::ApiClientBase.request -> self._session built by create_http_client in __init__. Shape: ApiClientBase.__init__ calls create_http_client and request() calls self._session.request, so the SDK retry policy handles a 503; reuse the _client helper with httpx.MockTransport in tests/test_sdk_centralization.py. | A test builds the client with a mock transport, sees a 503 then a 200, and gets one result Test: `tests/test_sdk_centralization.py::test_transient_status_is_retried_by_the_sdk_client`. |
