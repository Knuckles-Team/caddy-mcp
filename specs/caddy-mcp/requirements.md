Every requirement this specification owns, with the proof that closes it. Delivery state and

| ID | Requirement | Verification |
|---|---|---|
| `CONN-CADDY-MCP-R001` | **Connector reports its released version.** `caddy_mcp.__version__` equals the released `pyproject.toml` version and the bump configuration updates both. Caller chain: the `caddy-mcp` console script (pyproject.toml, scion_sdk.cli:serve) loads `caddy_mcp:connector` (caddy_mcp/__init__.py) whose Api is caddy_mcp/api_client.py::Api, and `__version__ = _v("caddy-mcp")` at caddy_mcp/api_client.py:8 reads the installed package metadata; tests/test_version.py does not exist yet (planned). Shape: caddy_mcp/api_client.py::__version__ already comes from importlib.metadata.version("caddy-mcp"), so it follows the pyproject.toml version of 2.3.9 with no second copy; the planned tests/test_version.py compares the two and no bump configuration exists to update. | `tests/test_version.py::test_reported_version_matches_the_released_package` |
| `CONN-CADDY-MCP-R002` | **Live-config writes require confirmation.** `caddy_load_config`, `caddy_put_config` and `caddy_patch_config` change the live proxy config, so each is a destructive tool that takes a `confirm` parameter, like `caddy_stop_server`. Caller chain: the `caddy-mcp` console script serves `caddy_mcp:connector`, whose Api methods `load_config`, `put_config` and `patch_config` in caddy_mcp/api/api_client_config.py carry `__http_method__ = "DELETE"`, so the SDK tool surface adds `confirm` and the destructive hint. Shape: with an elicitation-capable client the call asks for confirmation; with a stdio, no-auth or non-eliciting client a call without `confirm=true` returns the typed refusal `{cancelled: true, operation, reason}` whose reason says to repeat the call with confirm=true, never hangs and never reaches Caddy; a call with `confirm=true` runs on stdio and on HTTP. | `tests/test_config_confirm.py::test_stdio_no_auth_refuses_without_confirm_and_never_calls_caddy`, `tests/test_config_confirm.py::test_stdio_no_auth_succeeds_with_confirm_true`, `tests/test_config_confirm.py::test_http_refuses_without_confirm_then_succeeds_with_it` |
